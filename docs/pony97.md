# PONY97

PONY97.EXE is a standalone Windows 98 / Glide 2 turntable for Starling,
an original G4-inspired pony built with a 1997-style polygon and palette
budget. It uses GFALL's engine and embeds its model, palette and texture
in the executable. It needs no Daggerfall installation, ARENA2 directory,
MAIN.DAT, OBJ loader or external art at runtime.

## Build and run

The normal `make` / `make all` also builds and validates `build/PONY97.EXE`
and packages `build/pony97.iso`. To build just the pony viewer:

- `make pony97-check` builds `build/PONY97.EXE` and runs the existing PE
  validator: Windows 4.0 GUI, KERNEL32/USER32 imports only, runtime DLL
  binding, and no instructions beyond the Pentium MMX target.
- `make pony97-iso` validates the executable and creates `build/pony97.iso`.
  Its only files are PONY97.EXE and this note as README.TXT. It does not
  run hostcheck or include any game data or driver DLL.

The executable target needs `i686-w64-mingw32-gcc`; its validation also
needs `i686-w64-mingw32-objdump`, `file`, `grep` and `awk`. Packaging needs
`xorriso`. The standalone targets bypass the main dependency check because
that check requires Daggerfall data. The usual layer check still applies.

On the target, install the Voodoo Graphics driver and run PONY97.EXE,
or mount the ISO and run `D:\PONY97.EXE`. The engine loads the system's
`glide2x.dll` at runtime; do not put a copy on the disc. The renderer uses
its normal 640 x 480 Glide mode and W-buffer path.

## Controls

- Left / Right: orbit around the model.
- Up / Down: raise / lower the orbit, limited short of the poles.
- Plus / Minus: zoom, using the main keyboard or numeric keypad.
- Space: stop / start automatic rotation. Rotation starts enabled.
- R: restore the initial three-quarter view, zoom and automatic rotation.
- Escape: quit. With the engine console open, Escape closes it first.

Manual orbiting stops automatic rotation. Motion uses elapsed real time,
with a 100 ms step limit after a stall. The orbit pauses while the engine
console or another window has focus. Space and R are sampled during that
pause too, so holding one through it does not toggle on return. The usual
engine console, F3 frame rate and F12 screenshot remain available.

## Asset and rendering contract

`apps/pony97/pony_model.h` is generated by `assets/pony97/generate.py`.
The asset author owns that header and the OBJ/MTL/TGA exports; the viewer
includes the header only. Its present budget is 664 indexed vertices,
1,068 triangles and 50 RGB colours. Geometry is Y up, with front along +Z.
The pose is static, made of independent intersecting shells, without a rig.

At startup the app expands the indexed source into the engine's `Tri`
array, scaling each model unit to 64 engine units. That expanded array is
72,624 bytes for the present model, plus the read-only embedded source.
It builds one `Mesh`, one `Instance`, one measured `Bound`, and one `Level`.
Bad vertex or colour indices stop startup. The engine owns all clipping,
projection, depth buffering and Glide submission; no engine files change.

A single opaque 16 x 16 indexed picture contains texel index k at
`(k % 16, k / 16)`. Each triangle samples the centre of its colour's texel
at all three corners. Index zero is a normal opaque colour. Palette shades
are authored into the model, so daylight and point lighting are absent;
the viewer sets full brightness. Mipmaps start disabled: averaging this
swatch atlas would mix unrelated colours. Console changes to that setting
can alter the appearance and should be reset to off for asset inspection.

The app computes one outward plane equation per triangle at startup
(17,088 bytes for the present model). When the camera position changes,
a dot product against each cached plane marks front-facing triangles
with texture slot 0 and backfaces with the engine's documented 0xffff
skip sentinel. `draw_tris` skips those before any transform or submission.
Positions, UVs, triangle counts and measured bounds remain fixed. No
normalisation, square root, triangle copying or allocation is needed for
this visibility update; an unchanged camera reuses its last result.

This cull is required for the layered eye discs: their backs must not
show from the opposite side of the head. The engine intentionally keeps
isolated triangle faces two-sided, so simply adding a `Face` per triangle
would not reject those backs. The app uses the existing skip contract
without changing engine semantics. Its instance must remain at the
identity transform for the cached world-space plane test to stay valid.

There is one texture slot, no lights, no sky, no sprites, no sound startup
and no interaction polling.
Model occlusion is disabled because there is only one model. Texture and
mesh preparation happens once; the app makes no per-frame allocation,
mesh rebuild or texture upload. The help overlay is three short lines.

The orbit targets the measured bounding-box centre. Its enclosing sphere
sets the initial zoom, minimum distance and far clip. The closest zoom
keeps the complete sphere beyond the near plane; close inspection can
still crop the silhouette at the edges of the screen.

## Validation status

This change was authored and reviewed at source level under the standing
no-build instruction. No compiler, tests, PE checks, ISO generation or
hardware run was executed. Successful linking, the exact swatch sampling
on a real Glide driver, keyboard handling and frame rate on the MMX 233 /
Voodoo 1 remain target acceptance work. No frame-rate claim is made.
