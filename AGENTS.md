# AGENTS.md

## Project
- **Goal:** Recreate Daggerfall for Windows 98 on period hardware (Pentium MMX 233, 64 MB RAM, Voodoo 1, AWE64). Renders via 3dfx Glide 2; **glide2x.dll is loaded at runtime**.
- **Status:** Single-room block viewer (GFALL) plus tech demo (SPINTRI). This is a "from scratch" recreation for the 90s, not a port of the original source.
- **Reference:** Prefer public sources for formats and behavior: the [UESP wiki](https://en.uesp.net/wiki/Daggerfall:Daggerfall) (file formats, mechanics), plus community writeups such as the Daggerfall Unity docs and Interkarma's format notes. Do not treat `daggerfall/decompiled/` as authoritative; that decompilation is unreliable.

## Build (Linux, cross-compile)
**Required tools:** `i686-w64-mingw32-gcc` (or gcc-mingw-w64-i686-win32), `i686-w64-mingw32-objdump`, `xorriso`, and native `gcc` (for hostcheck). `sh tools/check-deps` names any that are missing.

**Primary targets:**
- `make` — Runs `tools/check-layers` and `tools/check-deps`, then `check`, builds `build/spintri.iso`, runs `gfall-check`, `renderfall-check`, and `levelfall-check`, builds `build/gfall.iso`.
- `make hostcheck` — **Only test.** Native build + run (`build/hostcheck`) against `daggerfall/DAGGER/ARENA2`. Writes `build/tex0.ppm`. Does not touch Glide or Windows.
- `make gfall-check` — Cross-builds `GFALL.EXE` and validates: PE32, 80386 GUI, Win95/NT4 subsystem/version, only `KERNEL32.dll` and `USER32.dll` imports, `LoadLibraryA`/`GetProcAddress` present, **no `glide2x.dll` import**, and rejects SSE/P6-specific instructions (cmov/fcmov/fucomi/fcomi/movaps/movss/addps/xmm).
- `make renderfall-check` / `make levelfall-check` — Same validator for `RENDERFALL.EXE` and `LEVELFALL.EXE`.
- `make check` — Same validator for `SPINTRI.EXE`. All four run the Makefile's one `pe_check`.
- `make layers` — `tools/check-layers` alone: no file includes a layer above its own (below).
- `make clean` — Removes `build/`.

**Execution (target):** Mount the ISO and run `D:\SPINTRI.EXE`, `D:\GFALL.EXE`, `D:\RENDERFALL.EXE`, or `D:\LEVELFALL.EXE`. **Do not copy glide2x.dll onto discs.** Escape quits.

## Architecture
Read `docs/architecture.md` before adding a file or a folder. The tree is in layers. A file includes its own layer and the ones below it, never one above, and `make` fails otherwise (`tools/check-layers`):

`src/engine/` ← `src/game/dagger/formats/` ← `src/game/dagger/tables/` ← `src/game/dagger/places/` ← `src/game/dagger/play/` ← `apps/`

Each game is one folder under `src/game/`, and today there is one, `src/game/dagger/`, holding all of Daggerfall: `formats` reads its files, `tables` holds its rules for dressing a place, `places` builds a place into the engine's `Level`, and `play` is the game proper, its player included. The engine knows Glide, Win98 and the 233, and no game: it has no player. It gives the camera, the walking body, using things and entities, and a game builds its own player out of them. A game never includes another game. `apps` holds the programs, `tests/` is hostcheck, and `tools/` holds scripts. The engine reaches a game only through hooks the game installs.

## Codebase layout
### Programs (`apps/`)
- `apps/gfall/main.c` — `GFALL.EXE`, the game: classic's title and start menu, then Privateer's Hold on foot, one `game_frame` a frame. Its entry. Same relationship to the engine as `apps/renderfall/main.c`: it links engine and dagger code and brings `WinMainCRTStartup`. Loads Privateer's Hold and hands a `Level` to `gfx.h`.
- `apps/levelfall/main.c` — `LEVELFALL.EXE`. Indexes every indoor (`MAPDITEM`) and outdoor (`MAPPITEM`) place at startup, filters by name, and flies through one. It is the engine's diagnostic view: cull and occlusion counts, texture residency, the clock and the weather, the sound and its sources, the frame profile, the triggers, F2/F3/F4/F5-F9/F11/P keys, F12 bookmarks. The left button or E uses what the view rests on, and a passage opens where it leads: into a house and out, down into a dungeon and up. "Stream World" in the list walks the whole map, streamed round the camera. The fly camera, the titled panels, and the cfg keys are `docs/viewers.md`. Same window and Glide path as renderfall.
- `apps/dfrec/main.c` — the `.DAT` tool, native: `import`, `dump`, `build` (text to a mod carrying only the fields it sets), `same`. `make hostcheck` runs its round trip (`datacheck`). Read `docs/data.md`.
- `apps/datfall/main.c` — `DATFALL.EXE`, a Windows 98 browser of races, enemies and weapons: the paper-doll IMG and CIF files, a creature's `TEXTURE` frames, and `WEAPON##.CIF` coloured by material. A normal maximized window, system list and buttons, no Glide. `make datfall-check` is its PE check and the host read of a Breton body pixel, the rat's front frame, and a dwarven weapon colour. Read `docs/data.md`.
- `apps/renderfall/main.c` — `RENDERFALL.EXE`, the ARCH3D model list and viewer (`docs/viewers.md`). `apps/spintri/main.c` — `SPINTRI.EXE`, the Glide text demo; it links nothing else.
### Engine (`src/engine/`)
- `src/engine/core/` — `df.h` types, endian helpers, x87 `df_sin`/`df_cos` (no libm), `df_iround`/`df_ifloor` (float to int without a rounding-mode switch), and `df_snap16` (the 1/16-pixel snap `glide.c` applies to every vertex), and `df_fpu_single`/`df_fpu_restore` (the x87's precision control, `docs/glide.md`). `mem.c` is the heap (stdlib malloc if `DF_HOST`, Win32 heap + CRT `memcpy`/`memmove`/`memset`/`strlen` replacements if not). `prof.c` is the frame profile by the cycle counter (`docs/profile.md`). `log.c` is the engine log: levels, a static line ring, a `printf` subset (`log_print`). Report through it, not `win_fail`, unless the program is about to stop.
- `src/engine/platform/` — `win32.c` (`_WinMainCRTStartup`, content dir beside the exe), `input.c` (movement, look, quit, a game's actions held, pressed and released, the walk among them, rebound and read back, a bind screen's key, and a menu's pointer; `keyname.c` names keys; `docs/input.md`), `fs.c` (POSIX if `DF_HOST`, Win32 otherwise; the original game's files under the root, `ARENA2`, and a game's own beside the program: `fs_open_beside`/`fs_read_beside`, a file or one folder deep, `fs_make_dir` for that folder, `fs_create` to write).
- `src/engine/assets/` — VFS over `fs` (`vfs_read` inside the root, `vfs_read_beside` beside the program), loader registry, engine formats: mesh, texture, palette, level, and `recfile.c`, a game's tables as self-describing binary chunks merged by id and field (`docs/data.md`).
- `src/engine/scene/` — placed meshes, billboards, lights (`light.c`: decals cut at load, only where the light can see, or per chunk of a stream under a budget; host-tested; `docs/lighting.md`), the world clock and calendar (`clock.c`: days counted, the months, week and start a `Calendar` the game installs, Tamriel's the default; the season) and the light by the hour (`daylight.c`: sun, moon, lamps; host-tested; `docs/daylight.md`), the weather (`weather.c`: kinds rolled from odds, blended; host-tested; `docs/weather.md`), collision (`collide.c`: swept ellipsoid against a per-frame gather; `body.c`: a body under gravity, as many as a game wants, each its own size; `walker.c`: the viewers' one body that follows the console's camera; host-tested; `docs/collision.md`), streaming (`stream.c`: a world loaded round the camera in chunk slots, the origin moved by whole chunks, under a cycle budget; a dungeon by block, 2048 chunks, its creatures and water in the slots, what the player changed kept as blocks go and come; host-tested; `docs/streaming.md`), interaction (`interact.c`: the use key's ray, what it takes within reach and not through a wall, what the body walks into, the movers that swing doors and run chained actions, and teleports; `keep.c`: the state that outlives a load, a row per mover or entity not as its file has it, by the game's key, a save game's world; host-tested; `docs/interact.md`), water (`Water` in `scene.h`: rectangles flooded to a level, how deep a body stands; `docs/water.md`), entities (`entity.c`: things that move on their own or stand where the game put them, a walking and a standing pose and the acts a game shows instead (attack, hurt, cast, shoot, dead), a frame the game can hold, drawn as the view of them the camera has, Daggerfall's five records and their mirrors; friend or foe is the game's; host-tested; `docs/entities.md`), transforms, visibility. Models and sprites whose box misses the view, sits past the fog or the far clip, or is wholly behind nearer walls in the occlusion cells, are not drawn. See `docs/culling.md`.
- `src/engine/gfx/` — `gfx.h` is the call the game makes. `glide.c` loads glide2x.dll at runtime (plain/`@N`/`_name@N`) and owns every Glide state: W-buffer, constant alpha, planar polygons, bind handles (`docs/glide.md`). `texcache.c` (one mip chain per picture, budgeted to the 2MB card at load, no per-frame upload; a streamed world's pictures, a whole place's pictures only entities wear, and every picture of a place past the card, instead through `texres.c`: a buddy allocator over TMU0, an 8 × 8 copy always there and sharper ones sent after the frame by distance under a byte budget, host-tested; `docs/streaming.md`), `mip.c` (builds the chains and the budget; a cutout's clear texels bleed only beside its opaque span; host-tested), `camera.c`, `rig.c` (a camera put on a body: first person at its eye, third person behind it, pulled in from walls; host-tested), `draw.c` (faces go out as one clipped polygon each), `sky.c` (an outdoor place's sky: four P_8 tiles under their own palette; when the hour changes the picture it comes in over frames, a piece read and a tile sent a frame, each tile under its own picture's palette; `docs/daylight.md`).
- `src/engine/sound/` — music and effects (`docs/sound.md`). `music.c` turns a whole song into Windows MIDI stream buffers once, at most 32 notes at once (an AWE64's hardware voices), and loops by giving finished buffers back; the card's synthesizer plays it. `mixer.c` mixes signed 8-bit clips into one stereo stream, C or MMX, bit for bit the same; `sound.c` is 16 voices, flat or from a point; `audio.c` puts the stream on the card (DirectSound primary written by us, one DirectSound buffer, or WINMM wave blocks), refilled from the frame, no thread; `ambience.c` decides, once a frame from `draw_frame`, the place's song, the weather's loops, thunder after lightning, the odd noise, and the scene's emitters. WINMM.DLL (`platform/winmm.c`) and DSOUND.DLL load at runtime. Host-tested but for the card.
- `src/engine/ui/` — HUD, text, and the console. Text draws a glyph sheet the game installed. With no sheet, the engine rasterizes the 8x8 Terminal strike (not the 8x12 stock OEM face). The built-in 8x8 face draws when that raster fails. The console is `console.c` (panel, keys through `win_pump`, engine commands) over `cmd.c` (command table, variables, history, completion; host-tested). Read `docs/console.md` before editing either; a new engine switch gets a `cmd_var` there.
- `src/engine/ui/pic.c` — a game's 2D pictures on the screen (`pic_load`, `pic_draw`, `pic_draw_part`): P_8 under their own palette or a 1555 cutout, cut in square tiles in a room on the card the game sets (`pic_set_room`), kept in memory and sent again with every place; host-tested on a fake card. Read `docs/pictures.md` before editing it or `glide_pic_palette`.
- `src/engine/scene/pack.c`, `src/engine/ui/packview.c` — a generic inventory: stacks, weight, money, equipment slots and moves between packs, under a catalogue the game gives, and a list screen over one or two packs, drawn through the game's text call. No game uses them yet; host-tested. Read `docs/pack.md` before editing either.
- `src/engine/scene/rpg.c`, `src/engine/ui/rpgview.c` — a character's numbers from rules the game gives: attributes spent from points, levels, vitals, one blow's to-hit and damage, and a screen drawn through the game's text call. No game uses them yet; host-tested. Read `docs/rpg.md` before editing either.
- `src/engine/ui/shot.c` — BMP screenshots. Reads the front buffer, writes the file beside the program, and draws the fading note. `console.c` only dispatches `screenshot` and pumps F12. Read `docs/console.md` before editing `shot.c`.
- `src/engine/ui/build.c` — the compile stamp in the bottom left. The Makefile passes the local time of the link as `BUILD_STAMP` (`YYYY-MM-DDTHH:MM:SS`). `version` turns the drawing on and off. Read `docs/console.md` before editing `build.c`.
### Daggerfall (`src/game/dagger/`)
- `formats/` — BSA (`bsa.c`), ARCH3D (`arch3d.c`; each face straightened to its real corners and its T-junctions welded inside the model, `docs/culling.md`), RDB (`rdb.c`), RMB (`rmb.c`; outdoor locations, and `rmb_load_interior` for one building's inside), COL (`palette.c`), TEXTURE.### (`texture.c`), FONT0000.FNT (`fnt.c`), the classes (`classcfg.c`; CLASS00..17.CFG), the CIF pictures, faces and the weapons' swings with each frame's place on classic's screen and the rectangle of its drawn pixels (`cif.c`), the HUD's and the menus' IMG pictures (`img.c`; uncompressed, with or without a header, under ART_PAL.COL or the palette a full screen carries; RAW pictures such as ARROW.RAW), the location index (`dungeon.c`; `MAPDITEM`/`MAPPITEM`, climates), the skies (`skyfile.c`; `SKY##.DAT` by climate, season, weather and hour, `NITE##I0.IMG` at night), the sound (`sndfile.c`; `DAGGER.SND`, clips by position) and the music (`hmi.c`; `MIDI.BSA`'s HMI songs), the world map (`worldmap.c`; `WOODS.WLD`'s heights, `CLIMATE.PAK`, every location's pixel), the climate ids (`climate.h`), and `bind.c` (registers the readers with the engine's loaders).
- `tables/` — MAIN.DAT and the mods over it (`maindat.c`: cooked on the first run from classic's FALL.EXE tables in `classic.c`, merged by id and field in `LOADORDR.TXT`'s order; `docs/data.md`), the weather odds by climate and season and each kind's look (`forecast.c`, records), Tamriel's calendar as month, weekday and calendar records installed in the clock when it differs (`calendar.c`), the classes, races and skills a character is built from (`careers.c`: CLAS from ARENA2, RACE and SKIL from classic), the weapon templates and materials (`items.c`: ITEM, WEAP, MATL from classic), `swaps.c` (Daggerfall Unity's climate and season swaps, and which pictures are windows, lit at night; `docs/daylight.md`), `sounds.c` (Daggerfall Unity's playlists, ambience and the flats that sound), and a dungeon's creatures in `enemies.c` (the kinds and the encounter tables as `ENEM` and `ENCT` records, classic's draws by the dungeon's type, the water rule; host-tested; `docs/entities.md`).
- `places/` — Privateer's Hold and every place loaded whole in `world.c` (`MAPDITEM.017`: `S0000999.RDB` at the origin tile plus four `B` border blocks, camera on editor marker 10; `world.c` makes an entity of each creature where its RDB marker stands; outdoors a street lamp light of each `TEXTURE.210` flat; everywhere an emitter of each flaming torch and animal; `world_load_inside` loads one building's inside where the building stands), the streamed world in `wild.c` (the land and the towns chunk by chunk, far ground baked, flora, the sky by the camera's pixel), the land's heights, tiles and meshes in `terrain.c` (DFU's sampler and tile rules, towns flat at their level; host-tested), the world's pictures and meshes in `wres.c` (`docs/streaming.md`), the townspeople walking a streamed town's streets in `people.c` (DFU's population and motor on each block's automap cells; host-tested; `docs/entities.md`), and `doors.c` (the doors, levers, passages and people a place's blocks name, as the engine's usables and movers; `docs/interact.md`), and `dunstream.c`, a dungeon streamed by block, the stream's chunk source for RDB blocks (creatures drawn at open in the blocks' order, attack, struck and dead poses, `dunstream_kind`, `dunstream_passive`; tested against the hold loaded whole; `docs/game.md`, `docs/streaming.md` Dungeons).

- `play/` — Daggerfall's game proper: its player, rules, screens and saves (`docs/game.md`). P1, on foot, is built:
  - `game.c`: the play state's frame, with Escape's pause and the use key;
  - `player.c`: a body under `rig_first`, classic's walk, run and jump;
  - `rules.c`: classic's sums, from DFU's formulas, host-tested (speeds, the vitals, a fall's damage);
  - `character.c` (P2): the character sheet, built by classic's rules from CLAS, RACE and SKIL; until creation, a Breton warrior;
  - `inventory.c` (P4): items made from ITEM, WEAP and MATL by classic's material rules, the pack and the weapon in hand, host-tested; `commands.c`: the game's console commands (`additem`, `items`, `equip`, `tgm`, `tai`); `weapon.c`: the weapon in hand over the view from its `WEAPON##.CIF`, a click's random swing at classic's rate, host-tested; `combat.c`: a swing's hit frame strikes the creature in reach by classic's to-hit and damage, health kept in its keep row, flinch and body, and a creature's blow at the player, host-tested; `foes.c`: creatures awake, seeing, chasing on bodies and striking, the console's `tai`, host-tested; `sfx.c`: DAGGER.SND's clips for combat, at a point or flat;
  - `overlay.c`: classic's compass from COMPASS.IMG and COMPBOX.IMG, the vitals bars from MAIN03 to MAIN05I0.IMG, the crosshair;
  - `menu.c` (P3): classic's title, start menu, options and controls screens with ARROW.RAW's pointer;
  - `keys.c`: the bindings in DATA\KEYS.DAT;
  - `screen.c`: classic's 320 × 200 on the card.

  What draws or reaches the keys (`screen.c`, `overlay.c`, `menu.c`, `keys.c`, `game.c`) is not built for the host (`PLAY_DRAW_SRC`).

## Critical constraints
- **Platform:** Windows 98, PE32 GUI, 80386, subsystem 4.0. No C runtime: `-nostdlib`, custom entry `_WinMainCRTStartup`. Only `KERNEL32.dll`/`USER32.dll` may be imported. `glide2x.dll` imported dynamically.
- **CPU:** `-march=pentium-mmx -mfpmath=387 -mno-sse`. The check forbids SSE/cm* and `xmm`-using insns — do not introduce them. In per-frame loops, turn floats into ints with `df_ifloor`/`df_iround`, not a C cast: on the x87 GCC emits `fnstcw`/`fldcw`/`fistp`/`fldcw` for each cast, about 30 cycles.
- **C:** `-std=gnu90` (C90 + GNU extensions). Math uses x87 inline asm (`df_sin`, `df_cos`, `fsqrt` in arch3d). Avoid `libm` calls.
- **Memory:** Win32 heap in `mem.c` (not C runtime malloc). Host uses libc malloc. Keep allocation consistent with the target side. A buffer allocated on first use and kept for the process uses `mem_keep`, not `mem_alloc`: LEVELFALL and RENDERFALL draw inside a temp heap that dies with each place. A `mem_alloc` buffer kept in a static to reuse on a later build records `mem_epoch()` with it and allocates again when the epoch has moved: the place's heap it came from may be gone.
- **Textures (Voodoo 1, 2MB TMU):** Must be square and power-of-two. A wall picture is stretched to powers of two (smoothly when its sides are not, `texture_smooth`) and tiled into `pot_w x pot_h` with subrect `span_w x span_h`; `pot_w % span_w == 0`, so it repeats. A picture only sprites use is padded instead (`texture_pad`): its own size in the corner, `span_w x span_h` = `width x height`, index 0 around it. An animated record's frames are one such padded square, a sheet of them side by side (`make_sheet`, `docs/sprites.md`). `world.c` decides once the palette is loaded. `glide.c` uploads `pot` with `cutout` flag to pack. hostcheck enforces both and sums bytes < 1500000.
- **Privateer's Hold:** The one loaded dungeon. Block list comes from `MAPDITEM.017`; tiles are 2048 units; the camera starts at marker record 10. Model faces store texture keys 119/120/122/123/124. The game builds one table from the location id and that place's climate: each key draws an offset 0..4 (a draw of 2 becomes 4) and adds it to the climate's crypt base. This hold is woodlands, so the keys become 323/322/319/322/320. Door set 74 (records 0..2), sewer set 168, and cave set 47 use the same family (374, 368, and 347 when the record exists). Sprites are not remapped. Asset paths use backslashes and an `ARENA2` directory beside the exe. That directory is not on the disc.
- **No SEH, no DLLs except those above.** Keep minimal imports.

## Conventions
- **Build first, test fast:** Use `make hostcheck` to verify logic on the host; then `make gfall-check` if changing Win32/Glide code paths.
- **Trust executable sources:** If public docs (UESP, format writeups) and this repo disagree about what the program does, trust Makefile + headers + source + existing build artifacts. This repo is instruction-heavy in its Makefile/checks.
- **Don't commit generated:** `build/` is build output. Keep `daggerfall/DAGGER/ARENA2` as-is (game data). `.gitignore` is standard C/MingW.
- **Minimal changes:** This aims for period accuracy. Avoid modern C or features that would trip the check scripts. If you modify `src/game/dagger/places/world.c` (hardcoded geometry/data counts), update `tests/check_dagger.c` accordingly.
- **Style:** gnu90 C. Comment non-obvious intent, format quirks, and constraints — this codebase is vibe-coded and has to be reviewable. Follow existing naming (snake_case). Keep Windows `WINVER`/`_WIN32_WINNT`/`WIN32_LEAN_AND_MEAN` in Win32/Glide files.
- **Document the change:** Behavior a later edit has to preserve goes in `docs/` before the commit, and the layout list above gains a line if the doc is new. Update the existing note (`docs/culling.md`, `docs/memory.md`, `docs/dungeons.md`, `docs/viewers.md`) when the change is one of those. A commit that changes what the frame draws, what is loaded, or a budget the next change must respect, without that note, is incomplete.

## Working in parallel
Several agent sessions work on this repo at once, each in its own checkout. The shared checkout at the repo root has `main`; other sessions use worktrees beside it (`../gfall-engine`).
- **Never edit another session's checkout.** Two sessions in one working tree break each other's builds mid-edit and sweep each other's files into commits.
- **Small slices, `main` moves often.** Before committing, rebase onto `main` and run a clean `make all`, which passes the layer check, hostcheck and every PE check.
- **Standing rule (the user's):** any session may fast-forward `main` to its commit once `make all` passes. Never rewrite `main`'s history (no rebase, reset or force on `main`), and never push; pushing stays the user's.
- **Stage files by name**, never `git add -A` or `git add .`: another session's files may be lying in the tree.
- **Say before touching shared files.** AGENTS.md, `docs/game.md`, the Makefile and the tests are edited by every session: message the session that owns the other side first, and after a fast-forward tell it to rebase.

## Debugging
- `build/*.dump` from objdump (PE info, imports) are produced during checks. Useful to inspect.
- `hostcheck` prints counts, bounds, texture info and writes `build/tex0.ppm`. The hardcoded expectations reflect the exact room kept.
- Glide binding is defensive (tries multiple name mangling) — don't "fix" it for modern toolchains.
