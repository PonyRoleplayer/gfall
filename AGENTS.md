# AGENTS.md

## Project
- **Goal:** Recreate Daggerfall for Windows 98 on period hardware (Pentium MMX 233, 64 MB RAM, Voodoo 1, AWE64). Renders via 3dfx Glide 2; **glide2x.dll is loaded at runtime**.
- **Status:** `GFALL.EXE` is the game: decomp-faithful Daggerfall (character creation, Privateer's Hold, the streamed world, towns and houses, combat, magic, quests, people and law, saves). LEVELFALL, RENDERFALL and DATFALL are viewers and SPINTRI the tech demo. It is a "from scratch" recreation for the 90s, not a port of the original source. There is one game, `src/game/dagger/`; the first-generation GFALL player (the "classic" game that used DFU's formulas) was retired on 2026-11-12 (git tag `before-gfall-retire`) and the decomp-faithful game, formerly GFALL, took its name and its tree. Its `` prefix is gone.
- **Roadmap and limits:** `docs/game-roadmap.md` (what is missing), `docs/game-later.md` (known bugs and gaps), `docs/game.md` (the design).
- **Reference:** The matching decompilation of FALL.EXE (`/home/shade/git/daggerfall-decomp`, unverified) is the game's rulebook, cross-checked by constants; read it, never copy it. Public sources for formats: the [UESP wiki](https://en.uesp.net/wiki/Daggerfall:Daggerfall), Daggerfall Unity docs, Interkarma's format notes. `daggerfall/decompiled/` is unreliable.

## Build (Linux, cross-compile)
**Required tools:** `i686-w64-mingw32-gcc` (or gcc-mingw-w64-i686-win32), `i686-w64-mingw32-objdump`, `xorriso`, and native `gcc` (for hostcheck). `sh tools/check-deps` names any that are missing.

**Primary targets:**
- `make` / `make all` — Runs `tools/check-layers` and `tools/check-deps`, then `check` (SPINTRI), builds `build/spintri.iso`, runs `gfall-check`, `renderfall-check`, `levelfall-check`, `datfall-check`, builds `build/gfall.iso` (which runs `build/hostcheck` first) and `pony97-iso`.
- `make hostcheck` — The tests: a native build run against `daggerfall/DAGGER/ARENA2` (engine, dagger data, maps, then the game's suites). Writes `build/*.ppm` and `build/*.wav`. Does not touch Glide or Windows.
- `make gfall-host` — The game's suites alone (`tests/check_game.c` and its siblings, `-DGFALL_HOST_MAIN`).
- `make gfall-check` — Cross-builds `GFALL.EXE` and validates: PE32, 80386 GUI, Win95/NT4 subsystem/version, only `KERNEL32.dll` and `USER32.dll` imports, `LoadLibraryA`/`GetProcAddress` present, **no `glide2x.dll` import**, no SSE/P6 instructions (cmov/fcmov/fucomi/fcomi/movaps/movss/addps/xmm); runs `tools/check-stack-probes`. `make gfall` builds the exe alone.
- `make renderfall-check` / `make levelfall-check` / `make datfall-check` / `make check` (SPINTRI) / `make pony97-check` / `make pony97-iso` — the same PE validator (`pe_check`) for the others; `docs/pony97.md` for PONY97.
- `make layers` — `tools/check-layers` alone: no file includes a layer above its own (below). `make clean` removes `build/`.

**Execution (target):** Mount the ISO and run `D:\GFALL.EXE`, `D:\RENDERFALL.EXE`, `D:\LEVELFALL.EXE`, `D:\DATFALL.EXE` or `D:\SPINTRI.EXE`. **Do not copy glide2x.dll onto discs.** Escape quits.

## Architecture
Read `docs/architecture.md` before adding a file or a folder. The tree is in layers. A file includes its own layer and the ones below it, never one above, and `make` fails otherwise (`tools/check-layers`):

`src/engine/` ← `src/game/dagger/formats/` ← `src/game/dagger/tables/` ← `src/game/dagger/places/` ← `src/game/dagger/play/` ← `apps/`

Each game is one folder under `src/game/`; today there is one, `src/game/dagger/`: `formats` reads Daggerfall's files, `tables` holds its rules and data (MAIN.DAT and the tables over it), `places` builds a place into the engine's `Level`, and `play` is the game proper, its player included. The engine knows Glide, Win98 and the 233, and no game: it has no player. A game never includes another game. `apps` holds the programs, `tests/` is hostcheck, `tools/` holds scripts. The engine reaches the game only through hooks it installs.

## Codebase layout
### Programs (`apps/`)
- `apps/gfall/main.c`, `apps/gfall/seam.c`, `apps/gfall/seam.h` — `GFALL.EXE`: character creation, then Privateer's Hold and out into the world, one `play_frame` a frame. `main.c` is the Win32/Glide entry; `seam.c` alone adapts dagger data (places, doors, people, the stream, travel maps) to the game's hooks. The game owns a pointer-free state and its own versioned save codec under `gfall/saves`; preferences and all bindings live in readable `gfall/settings.cfg`. See `docs/game.md`, `docs/game-roadmap.md`, `docs/game-later.md`, `docs/game-people.md`, `docs/game-quests.md`.
- `apps/levelfall/main.c` — `LEVELFALL.EXE`. Indexes every indoor (`MAPDITEM`) and outdoor (`MAPPITEM`) place at startup, filters by name, and flies through one. It is the engine's diagnostic view: cull and occlusion counts, texture residency, the clock and the weather, the sound and its sources, the frame profile, the triggers, F2/F3/F4/F5-F9/F11/P keys, F12 bookmarks. The left button or E uses what the view rests on, and a passage opens where it leads: into a house and out, down into a dungeon and up. "Stream World" in the list walks the whole map, streamed round the camera. The fly camera, the titled panels, and the cfg keys are `docs/viewers.md`. Same window and Glide path as renderfall.
- `apps/dfrec/main.c` — the `.DAT` tool, native: `import`, `dump`, `build` (text to a mod carrying only the fields it sets), `same`. `make hostcheck` runs its round trip (`datacheck`). Read `docs/data.md`.
- `apps/datfall/main.c` — `DATFALL.EXE`, a Windows 98 construction set, read-only. A normal maximized window with two tabs, no Glide. Commons is a tree, a record list, a preview and a field grid. Data is every MAIN.DAT table and each file `DATA\LOADORDR.TXT` names, plus the merge (`books.c`). Pictures is every `TEXTURE.###`, a thumbnail grid and an animated frame (`pics.c`). Characters is each race's paper doll from the `RACE` file names, and a strip of every head (`paper.c`). Creatures is each kind's walk, attack, hurt, stand and corpse, five views, animated (`beast.c`). Items is each weapon in each material, its CIF recoloured and the made weight, value and condition (`made.c`). World, the other tab, is the height-shaded map on the left, zoomed and scrolled, and every dungeon and town in the panel on the right (`atlas.c`). `make datfall-check` is its PE check and the host read: every chunk's field names, a mod's new field, 472 texture archives, `TEXTURE.255`'s 20 records, a Breton body pixel, Breton's 10 male heads, the rat's poses (walk 0..4, stand 15..19, corpse `TEXTURE.401` record 1), the rat's front frame, a dwarven weapon colour, a steel longsword at 5.50 kg, value 90, condition 1200, the 1000×500 map with Daggerfall at pixel 207,213, 4232 dungeons and 15251 outdoor places. Read `docs/data.md`.
- `apps/renderfall/main.c` — `RENDERFALL.EXE`, the ARCH3D model list and viewer (`docs/viewers.md`). `apps/spintri/main.c` — `SPINTRI.EXE`, the Glide text demo; it links nothing else.
- `apps/pony97/main.c` — `PONY97.EXE`, an embedded-model Glide turntable with arrows, Space, +/- and R. Links the engine alone; generated `pony_model.h` and `assets/pony97/` supply the art. One 16 x 16 opaque indexed swatch texture, baked palette shading, startup mesh conversion and no per-frame app allocations. Read `docs/pony97.md`.
### Engine (`src/engine/`)
- `src/engine/core/` — `df.h` types, endian helpers, x87 `df_sin`/`df_cos` (no libm), `df_iround`/`df_ifloor` (float to int without a rounding-mode switch), and `df_snap16` (the 1/16-pixel snap `glide.c` applies to every vertex), the view's size (`view.c`: `df_view_w()`/`df_view_h()` and the centre, set when Glide opens its mode, 640 x 480 before; `DF_VIEW_W`/`DF_VIEW_H` the same under the old names; `DF_VIEW_MAX_W`/`_H` for static buffers; `docs/glide.md`, The screen's mode), and `df_fpu_single`/`df_fpu_restore` (the x87's precision control, `docs/glide.md`). `cpu.c` caches the guarded CPUID MMX capability for graphics and sound (non-x86 returns false; `docs/glide.md`, Runtime mip averaging). `mem.c` is the heap (stdlib malloc if `DF_HOST`, Win32 heap + CRT `memcpy`/`memmove`/`memset`/`strlen` replacements if not). `prof.c` is the frame profile by the cycle counter (`docs/profile.md`). `log.c` is the engine log: levels, a static line ring, a `printf` subset (`log_print`). Report through it, not `win_fail`, unless the program is about to stop.
- `src/engine/platform/` — `win32.c` (`_WinMainCRTStartup`, content dir beside the exe), `input.c` (movement, look, quit, a game's actions held, pressed and released, the walk among them, rebound and read back, a bind screen's key, and a menu's pointer; `keyname.c` names keys; `docs/input.md`), `fs.c` (POSIX if `DF_HOST`, Win32 otherwise; the original game's files under the root, `ARENA2`, and a game's own beside the program, any depth (`saves\Anna Smith\S0003.SAV`), a name that could leave that folder refused: `fs_open_beside`/`fs_read_beside`, `fs_make_dir`/`fs_make_dirs`, `fs_create` to write, `fs_list` a folder, `fs_exists`, `fs_delete`, `fs_remove_dir` an empty folder, `fs_move` replacing a file without losing it (Win98 has no replacing rename: the old waits as `.OLD`), `fs_local_time`; host-tested).
- `src/engine/assets/` — VFS over `fs` (`vfs_read` inside the root, `vfs_read_beside` beside the program), loader registry, engine formats: mesh, texture, palette, level, and `recfile.c`, a game's tables as self-describing binary chunks merged by id and field (`docs/data.md`).
- `src/engine/scene/` — placed meshes, billboards, lights (`light.c`: decals cut at load, only where the light can see, or per chunk of a stream under a budget; host-tested; `docs/lighting.md`), the world clock and calendar (`clock.c`: days counted, the months, week and start a `Calendar` the game installs, Tamriel's the default; host-tested; `docs/collision.md`), streaming (`stream.c`: a world loaded round the camera in chunk slots, the origin moved by whole chunks, under a cycle budget; a dungeon by block, 2048 chunks, its creatures and water in the slots, what the player changed kept as blocks go and come; host-tested; `docs/streaming.md`), interaction (`interact.c`: the use key's ray, what it takes within reach and not through a wall, what the body walks into, the movers that swing doors and run chained actions, and teleports; - `src/engine/sound/` — music and effects (`docs/sound.md`). `music.c` turns a whole song into Windows MIDI stream buffers once, at most 32 notes at once (an AWE64's hardware voices), and loops by giving finished buffers back; the card's synthesizer plays it. `mixer.c` mixes signed 8-bit clips into one stereo stream, C or MMX, bit for bit the same; `sound.c` is 16 voices, flat or from a point; `audio.c` puts the stream on the card (DirectSound primary written by us, one DirectSound buffer, or WINMM wave blocks), refilled from the frame, no thread; `ambience.c` decides, once a frame from `draw_frame`, the place's song, the weather's loops, thunder after lightning, the odd noise, and the scene's emitters. ## Critical constraints
- **Platform:** Windows 98, PE32 GUI, 80386, subsystem 4.0. No C runtime: `-nostdlib`, custom entry `_WinMainCRTStartup`. Only `KERNEL32.dll`/`USER32.dll` may be imported. `glide2x.dll` imported dynamically.
- **CPU:** `-march=pentium-mmx -mfpmath=387 -mno-sse`. The check forbids SSE/cm* and `xmm`-using insns — do not introduce them. In per-frame loops, turn floats into ints with `df_ifloor`/`df_iround`, not a C cast: on the x87 GCC emits `fnstcw`/`fldcw`/`fistp`/`fldcw` for each cast, about 30 cycles.
- **C:** `-std=gnu90` (C90 + GNU extensions). Math uses x87 inline asm (`df_sin`, `df_cos`, `fsqrt` in arch3d). Avoid `libm` calls.
- **Memory:** Win32 heap in `mem.c` (not C runtime malloc). Host uses libc malloc. Keep allocation consistent with the target side. A buffer allocated on first use and kept for the process uses `mem_keep`, not `mem_alloc`: LEVELFALL and RENDERFALL draw inside a temp heap that dies with each place. A `mem_alloc` buffer kept in a static to reuse on a later build records `mem_epoch()` with it and allocates again when the epoch has moved: the place's heap it came from may be gone.
- **Textures (Voodoo 1, 2MB TMU):** Must be square and power-of-two. A wall picture is stretched to powers of two (smoothly when its sides are not, `texture_smooth`) and tiled into `pot_w x pot_h` with subrect `span_w x span_h`; `pot_w % span_w == 0`, so it repeats. A picture only sprites use is padded instead (`texture_pad`): its own size in the corner, `span_w x span_h` = `width x height`, index 0 around it. An animated record's frames are one such padded square, a sheet of them side by side (`make_sheet`, `docs/sprites.md`). `world.c` decides once the palette is loaded. `glide.c` uploads `pot` with `cutout` flag to pack. hostcheck enforces both and sums bytes < 1500000.
- **Privateer's Hold:** The one loaded dungeon. Block list comes from `MAPDITEM.017`; tiles are 2048 units; the camera starts at marker record 8, the cave by the campfire (record 10 stands beside the way out). Model faces store texture keys 119/120/122/123/124. The game builds one table from the location id and that place's climate: each key draws an offset 0..4 (a draw of 2 becomes 4) and adds it to the climate's crypt base. This hold is woodlands, so the keys become 323/322/319/322/320. Door set 74 (records 0..2), sewer set 168, and cave set 47 use the same family (374, 368, and 347 when the record exists). Sprites are not remapped. Asset paths use backslashes and an `ARENA2` directory beside the exe. That directory is not on the disc.
- **No SEH, no DLLs except those above.** Keep minimal imports.

## Conventions
- **Build first, test fast:** Use `make hostcheck` to verify logic on the host; then `make gfall-check` if changing Win32/Glide code paths.
- **Trust executable sources:** If public docs (UESP, format writeups) and this repo disagree about what the program does, trust Makefile + headers + source + existing build artifacts. This repo is instruction-heavy in its Makefile/checks.
- **Don't commit generated:** `build/` is build output. Keep `daggerfall/DAGGER/ARENA2` as-is (game data). `.gitignore` is standard C/MingW.
- **Minimal changes:** This aims for period accuracy. Avoid modern C or features that would trip the check scripts. If you modify `src/game/dagger/places/world.c` (hardcoded geometry/data counts), update `tests/check_dagger.c` accordingly.
- **Style:** gnu90 C. Comment non-obvious intent, format quirks, and constraints — this codebase is vibe-coded and has to be reviewable. Follow existing naming (snake_case). Keep Windows `WINVER`/`_WIN32_WINNT`/`WIN32_LEAN_AND_MEAN` in Win32/Glide files.
- **Document the change:** Behavior a later edit has to preserve goes in `docs/` before the commit, and the layout list above gains a line if the doc is new. Update the existing note (`docs/culling.md`, `docs/memory.md`, `docs/dungeons.md`, `docs/viewers.md`) when the change is one of those. A commit that changes what the frame draws, what is loaded, or a budget the next change must respect, without that note, is incomplete.

## Working in parallel
The trunk is `main`; the `OGFALL` branch it came from is retired.
Several agent sessions work on this repo at once, each in its own checkout. The shared checkout at the repo root has `main`; other sessions use worktrees beside it (`../gfall-engine`).
- **Never edit another session's checkout.** Two sessions in one working tree break each other's builds mid-edit and sweep each other's files into commits.
- **Small slices, `main` moves often.** Before committing, rebase onto `main` and run a clean `make all`, which passes the layer check, hostcheck and every PE check.
- **Standing rule (the user's):** any session may fast-forward `main` to its commit once `make all` passes. Never rewrite `main`'s history (no rebase, reset or force on `main`), and never push; pushing stays the user's.
- **Stage files by name**, never `git add -A` or `git add .`: another session's files may be lying in the tree.
- **Say before touching shared files.** AGENTS.md, `docs/game.md`, the Makefile and the tests are edited by every session: message the session that owns the other side first, and after a fast-forward tell it to rebase.

## Debugging
- `build/*.dump` from objdump (PE info, imports) are produced during checks. Useful to inspect.
- `hostcheck` prints counts, bounds, texture info and writes `build/tex0.ppm`. The hardcoded expectations reflect the exact room kept.
- Glide binding is defensive (tries multiple name mangling) — don't "fix" it for modern toolchains.
