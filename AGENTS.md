# AGENTS.md

## Project
- **Goal:** Recreate Daggerfall for Windows 98 on period hardware (Pentium MMX 233, 64 MB RAM, Voodoo 1, AWE64). Renders via 3dfx Glide 2; **glide2x.dll is loaded at runtime**.
- **Status:** Single-room block viewer (GFALL) plus tech demo (SPINTRI). This is a "from scratch" recreation for the 90s, not a port of the original source.
- **Reference:** Prefer public sources for formats and behavior: the [UESP wiki](https://en.uesp.net/wiki/Daggerfall:Daggerfall) (file formats, mechanics), plus community writeups such as the Daggerfall Unity docs and Interkarma's format notes. Do not treat `daggerfall/decompiled/` as authoritative; that decompilation is unreliable.

## Build (Linux, cross-compile)
**Required tools:** `i686-w64-mingw32-gcc` (or gcc-mingw-w64-i686-win32), `i686-w64-mingw32-objdump`, `xorriso`, and native `gcc` (for hostcheck). These are **not present** in this environment; build artifacts already exist in `build/`.

**Primary targets:**
- `make` — Runs `check`, builds `build/spintri.iso`, runs `gfall-check`, `renderfall-check`, and `levelfall-check`, builds `build/gfall.iso`.
- `make hostcheck` — **Only test.** Native build + run (`build/hostcheck`) against `daggerfall/DAGGER/ARENA2`. Writes `build/tex0.ppm`. Does not touch Glide or Windows.
- `make gfall-check` — Cross-builds `GFALL.EXE` and validates: PE32, 80386 GUI, Win95/NT4 subsystem/version, only `KERNEL32.dll` and `USER32.dll` imports, `LoadLibraryA`/`GetProcAddress` present, **no `glide2x.dll` import**, and rejects SSE/P6-specific instructions (cmov/fcmov/fucomi/fcomi/movaps/movss/addps/xmm).
- `make renderfall-check` / `make levelfall-check` — Same validator for `RENDERFALL.EXE` and `LEVELFALL.EXE`.
- `make check` — Same validator for `SPINTRI.EXE`.
- `make clean` — Removes `build/`.

**Execution (target):** Mount the ISO and run `D:\SPINTRI.EXE`, `D:\GFALL.EXE`, `D:\RENDERFALL.EXE`, or `D:\LEVELFALL.EXE`. **Do not copy glide2x.dll onto discs.** Escape quits.

## Codebase layout
- `game/daggerfall/main.c` — `GFALL.EXE` entry. Same relationship to the engine as `tools/renderfall/main.c`: it links engine and dagger code and brings `WinMainCRTStartup`. Loads Privateer's Hold and hands a `Level` to `gfx.h`.
- `src/engine/core/` — `df.h` types, endian helpers, x87 `df_sin`/`df_cos` (no libm), `df_iround`/`df_ifloor` (float to int without a rounding-mode switch), and `df_snap16` (the 1/16-pixel snap `glide.c` applies to every vertex). `mem.c` is the heap (stdlib malloc if `DF_HOST`, Win32 heap + CRT `memcpy`/`memmove`/`memset`/`strlen` replacements if not). `log.c` is the engine log: levels, a static line ring, a `printf` subset (`log_print`). Report through it, not `win_fail`, unless the program is about to stop.
- `src/engine/platform/` — `win32.c` (`_WinMainCRTStartup`, content dir beside the exe), `input.c`, `fs.c` (POSIX if `DF_HOST`, Win32 otherwise).
- `src/engine/assets/` — VFS over `fs`, loader registry, engine formats: mesh, texture, palette, level.
- `src/engine/scene/` — placed meshes, billboards, lights (`light.c`: decals cut at load, host-tested; `docs/lighting.md`), the world clock (`clock.c`) and the light by the hour (`daylight.c`: sun, moon, lamps; host-tested; `docs/daylight.md`), the weather (`weather.c`: kinds rolled from odds, blended; host-tested; `docs/weather.md`), collision (`collide.c`: swept ellipsoid against a per-frame gather; `walker.c`: the body that follows the camera under gravity; host-tested; `docs/collision.md`), transforms, visibility. Models and sprites whose box misses the view, sits past the fog or the far clip, or is wholly behind nearer walls in the occlusion cells, are not drawn. See `docs/culling.md`.
- `src/engine/gfx/` — `gfx.h` is the call the game makes. `glide.c` loads glide2x.dll at runtime (plain/`@N`/`_name@N`) and owns every Glide state: W-buffer, constant alpha, planar polygons, bind handles (`docs/glide.md`). `texcache.c` (one mip chain per picture, budgeted to the 2MB card at load, no per-frame upload), `mip.c` (builds the chains and the budget; host-tested), `camera.c`, `draw.c` (faces go out as one clipped polygon each), `sky.c` (an outdoor place's sky: four P_8 tiles under their own palette, sent again when the hour changes the picture; `docs/daylight.md`).
- `src/engine/sound/` — music and effects (`docs/sound.md`). `music.c` turns a whole song into Windows MIDI stream buffers once, at most 32 notes at once (an AWE64's hardware voices), and loops by giving finished buffers back; the card's synthesizer plays it. `mixer.c` mixes signed 8-bit clips into one stereo stream, C or MMX, bit for bit the same; `sound.c` is 16 voices, flat or from a point; `audio.c` puts the stream on the card (DirectSound primary written by us, one DirectSound buffer, or WINMM wave blocks), refilled from the frame, no thread; `ambience.c` decides, once a frame from `draw_frame`, the place's song, the weather's loops, thunder after lightning, the odd noise, and the scene's emitters. WINMM.DLL (`platform/winmm.c`) and DSOUND.DLL load at runtime. Host-tested but for the card.
- `src/engine/ui/` — HUD, text, and the console. Text draws a glyph sheet the game installed. With no sheet, the engine rasterizes the 8x8 Terminal strike (not the 8x12 stock OEM face). The built-in 8x8 face draws when that raster fails. The console is `console.c` (panel, keys through `win_pump`, engine commands) over `cmd.c` (command table, variables, history, completion; host-tested). Read `docs/console.md` before editing either; a new engine switch gets a `cmd_var` there.
- `src/engine/ui/shot.c` — BMP screenshots. Reads the front buffer, writes the file beside the program, and draws the fading note. `console.c` only dispatches `screenshot` and pumps F12. Read `docs/console.md` before editing `shot.c`.
- `src/engine/ui/build.c` — the compile stamp in the bottom left. The Makefile passes the local time of the link as `BUILD_STAMP` (`YYYY-MM-DDTHH:MM:SS`). `version` turns the drawing on and off. Read `docs/console.md` before editing `build.c`.
- `src/game/dagger/` — BSA, ARCH3D (each face straightened to its real corners and its T-junctions welded inside the model, `docs/culling.md`), RDB, RMB, COL, TEXTURE.###, FONT0000.FNT, Privateer's Hold in `dungeon.c`/`world.c` (`MAPDITEM.017`: `S0000999.RDB` at the origin tile plus four `B` border blocks, camera on editor marker 10), outdoor locations in `rmb.c`, the skies in `skyfile.c` (`SKY##.DAT` by climate, season, weather and hour, `NITE##I0.IMG` at night), the weather odds by climate and season in `forecast.c`, the sound in `sndfile.c` (`DAGGER.SND`, clips by position), `hmi.c` (`MIDI.BSA`'s HMI songs) and `sounds.c` (Daggerfall Unity's playlists, ambience and the flats that sound), and `player.c` (WASD/Q/E, mouse look). Outdoors `world.c` makes a street lamp light of each `TEXTURE.210` flat; everywhere an emitter of each flaming torch and animal.
- `tools/levelfall/main.c` — `LEVELFALL.EXE`. Indexes every indoor (`MAPDITEM`) and outdoor (`MAPPITEM`) place at startup, filters by name, and flies through one. It is the engine's diagnostic view: cull and occlusion counts, texture residency, the clock and the weather, the sound and its sources, F2/F4/F5-F9 keys, F12 bookmarks. The fly camera, the titled panels, and the cfg keys are `docs/viewers.md`. Same window and Glide path as renderfall.
- `tools/hostcheck.c` — runs `check_engine.c` then `check_dagger.c`. Engine tests cover transforms, camera, visibility, loaders, VFS, the console's log, commands, history, and line editing, the mip chains and texture budget, the light decals and sprite tints, the clock and the light by the hour, the weather's rolls and blends, the walker on a course of floor, wall, stair and block, a flame's flicker, and the sound (the MMX and C mixers bit for bit, pan and reach, voice stealing, the song sort, the 32-voice limit). Dagger tests assert the hold (models, sprites standing on its floors, the torch's sheet of four frames, 71 lights with its flames flickering, start marker, no sky), the dungeon list (4232 records, Privateer's Hold in region 17), the outdoor list (15251, Daggerfall region 17 block `WALLAA02.RMB`, one farmstead loads with a sky and a light per lamp flat), the sky files (climate to file, hour to frame, east half first in the morning, weather to file) and the weather odds, the sound files (459 clips, 131 songs that read within 32 voices, every playlist's song present), the hold's torches heard and a farm's storm louder than its sun, texture POT/square tiling for walls and padding for sprites, and write `build/tex0.ppm` and `build/snd0.wav`/`snd1.wav` (a torch, a storm). **Update the dagger test when world/loading changes.**
- `docs/dungeons.md` — dungeon record layout, climate, and which loader to call. Read this before editing `dungeon.c` or `world.c`.
- `docs/viewers.md` — RENDERFALL and LEVELFALL list UI, keys, and the temp heap. Read this before editing either viewer.
- `docs/culling.md` — block spans, baked boxes, and ARCH3D face cull. Read this before editing `scene.c`, the far clip, or fog.
- `docs/console.md` — the engine console, its log, and the commands that change a live frame. Read this before editing `console.c`.
- `docs/memory.md` — heap, the shared mesh cache, and the 2MB texture card. Read this before editing `world.c`, `texcache.c`, or `glide.c` uploads.
- `docs/glide.md` — the Glide state, what each triangle sends the card, depth, polygons, cutouts, and binding. Read this before editing `glide.c` or `draw.c`'s submission.
- `docs/lighting.md` — the RDB light records, the ambient tint, and the light decals. Read this before editing `light.c`, the light pass in `draw.c`, or the light records in `rdb.c`.
- `docs/sprites.md` — where a flat stands (an RDB point is its centre, an RMB point its base), animated records as one sheet of frames, rates and phases. Read this before editing how `world.c` places flats, `make_sheet`, `draw_flat`, or the frames in `texture.c`.
- `docs/collision.md` — the body, the swept-ellipsoid sweep, the gather, a frame of walking, stuck. Read this before editing `collide.c`, `walker.c`, or the walker's call in `draw.c`.
- `docs/weather.md` — the weather's kinds, rolls and blends, the odds, and what it does to light, fog, cull, sky, rain, snow and lightning. Read this before editing `weather.c`, `forecast.c`, or the weather code in `draw.c`.
- `docs/sound.md` — how Daggerfall's music and effects work (DAGGER.SND, MIDI.BSA's HMI, when each plays), the MIDI stream and the 32-voice limit, the mixer and the ways onto the card, a frame of ambience, memory, switches. Read this before editing `src/engine/sound/`, `winmm.c`, `sndfile.c`, `hmi.c`, `sounds.c`, or the sound call in `draw.c`.
- `docs/daylight.md` — the world clock, the sky files and how the sky is drawn, sun and moon light per face, and the street lamps. Read this before editing `clock.c`, `daylight.c`, `sky.c`, `skyfile.c`, the sky pass or the outdoor light in `draw.c`, or `glide_sky`.
- `daggerfall/DAGGER/ARENA2/` — Game data used at runtime and by hostcheck. Not copied onto the discs. The executables still look for `ARENA2` beside themselves.
- `third_party/glide2/include/` — Glide 2 headers.

## Critical constraints
- **Platform:** Windows 98, PE32 GUI, 80386, subsystem 4.0. No C runtime: `-nostdlib`, custom entry `_WinMainCRTStartup`. Only `KERNEL32.dll`/`USER32.dll` may be imported. `glide2x.dll` imported dynamically.
- **CPU:** `-march=pentium-mmx -mfpmath=387 -mno-sse`. The check forbids SSE/cm* and `xmm`-using insns — do not introduce them. In per-frame loops, turn floats into ints with `df_ifloor`/`df_iround`, not a C cast: on the x87 GCC emits `fnstcw`/`fldcw`/`fistp`/`fldcw` for each cast, about 30 cycles.
- **C:** `-std=gnu90` (C90 + GNU extensions). Math uses x87 inline asm (`df_sin`, `df_cos`, `fsqrt` in arch3d). Avoid `libm` calls.
- **Memory:** Win32 heap in `mem.c` (not C runtime malloc). Host uses libc malloc. Keep allocation consistent with the target side. A buffer allocated on first use and kept for the process uses `mem_keep`, not `mem_alloc`: LEVELFALL and RENDERFALL draw inside a temp heap that dies with each place. A `mem_alloc` buffer kept in a static to reuse on a later build records `mem_epoch()` with it and allocates again when the epoch has moved: the place's heap it came from may be gone.
- **Textures (Voodoo 1, 2MB TMU):** Must be square and power-of-two. A wall picture is stretched to powers of two (smoothly when its sides are not, `texture_smooth`) and tiled into `pot_w x pot_h` with subrect `span_w x span_h`; `pot_w % span_w == 0`, so it repeats. A picture only sprites use is padded instead (`texture_pad`): its own size in the corner, `span_w x span_h` = `width x height`, index 0 around it. An animated record's frames are one such padded square, a sheet of them side by side (`make_sheet`, `docs/sprites.md`). `world.c` decides once the palette is loaded. `glide.c` uploads `pot` with `cutout` flag to pack. hostcheck enforces both and sums bytes < 1500000.
- **Privateer's Hold:** The one loaded dungeon. Block list comes from `MAPDITEM.017`; tiles are 2048 units; the camera starts at marker record 10. Model faces store texture keys 119/120/122/123/124. The game builds one table from the location id and that place's climate: each key draws an offset 0..4 (a draw of 2 becomes 4) and adds it to the climate's crypt base. This hold is woodlands, so the keys become 323/322/319/322/320. Door set 74 (records 0..2), sewer set 168, and cave set 47 use the same family (374, 368, and 347 when the record exists). Sprites are not remapped. Asset paths use backslashes and an `ARENA2` directory beside the exe. That directory is not on the disc.
- **No SEH, no DLLs except those above.** Keep minimal imports.

## Conventions
- **Build first, test fast:** Use `make hostcheck` to verify logic on the host; then `make gfall-check` if changing Win32/Glide code paths.
- **Trust executable sources:** If public docs (UESP, format writeups) and this repo disagree about what the program does, trust Makefile + headers + source + existing build artifacts. This repo is instruction-heavy in its Makefile/checks.
- **Don't commit generated:** `build/` is build output. Keep `daggerfall/DAGGER/ARENA2` as-is (game data). `.gitignore` is standard C/MingW.
- **Minimal changes:** This aims for period accuracy. Avoid modern C or features that would trip the check scripts. If you modify `src/game/dagger/world.c` (hardcoded geometry/data counts), update `tools/check_dagger.c` accordingly.
- **Style:** gnu90 C. Comment non-obvious intent, format quirks, and constraints — this codebase is vibe-coded and has to be reviewable. Follow existing naming (snake_case). Keep Windows `WINVER`/`_WIN32_WINNT`/`WIN32_LEAN_AND_MEAN` in Win32/Glide files.
- **Document the change:** Behavior a later edit has to preserve goes in `docs/` before the commit, and the layout list above gains a line if the doc is new. Update the existing note (`docs/culling.md`, `docs/memory.md`, `docs/dungeons.md`, `docs/viewers.md`) when the change is one of those. A commit that changes what the frame draws, what is loaded, or a budget the next change must respect, without that note, is incomplete.

## Debugging
- `build/*.dump` from objdump (PE info, imports) are produced during checks. Useful to inspect.
- `hostcheck` prints counts, bounds, texture info and writes `build/tex0.ppm`. The hardcoded expectations reflect the exact room kept.
- Glide binding is defensive (tries multiple name mangling) — don't "fix" it for modern toolchains.
